# 封锁窗口提前结束 + 换班：调度收尾模拟

模拟"正在执行的封锁窗口被调度提前结束、同时换班"的收尾过程。系统**只辅助记录和检查**，
不自行下达设备操作指令，不强制改写任何步骤状态；所有收尾动作均为待负责人确认的建议。

## 结构

- `blockade/models.py` — 领域模型：步骤（含**可中断点**与**撤离所需时间**配置）、
  封锁窗口、许可（版本递增）、确认、交接班、收尾建议、异常协调状态。
- `blockade/operation.py` — 记录与检查核心 `BlockadeOperation`：窗口压缩/恢复、
  交接发起/接收、保护撤销、确认登记、收尾建议生成/确认、异常协调闭合、完成销记。
- `blockade/errors.py` — 被检查拦截的违规操作。
- `tests/test_combined_scenario.py` — 组合请求测试：窗口压缩后又恢复 + 交班确认迟到
  + 部分保护确认撤销。
- `tests/test_invariants.py` — 逐条不变量测试。

## 钉住的约束

1. **退出条件即配置**：每个步骤配置可中断点（到达时间）与撤离时间；安全退出所需时间
   = 最近可中断点到达时间 + 撤离时间。无可中断点的执行中步骤视为"无法安全退出"。
2. **时间不足进入异常协调**：压缩后剩余时间不足以满足已配置退出条件（或存在无法安全
   退出的步骤）时，进入明确的 `EXCEPTION_COORDINATION` 状态；只由负责人显式闭合，
   窗口恢复或许可变化都不自动清除。系统**不会**把任何步骤强制改成完成。
3. **交接未闭合禁止销记**：旧班交出责任前新班必须确认接收；确认前责任仍属旧班，
   迟到确认被标记。交接未闭合时 `sign_off_completion` 一律拒绝。
4. **收尾建议待确认**：窗口压缩/恢复、保护撤销都会重新生成收尾建议（旧待确认建议被
   取代），必须由**当前负责人**确认；销记前不允许存在待确认建议。
5. **许可版本递增**：许可每次变更（失效/重新签发）版本严格 +1。过期确认、版本不符
   的确认一律拒绝；任何确认都**不得恢复已失效的开工资格**，资格只能经人工重新签发
   （新版本）恢复。许可失效期间禁止记录开工/完工（安全类的停点/撤离记录随时允许）。
6. **系统边界**：`issue_equipment_command` 一律抛 `EquipmentCommandForbidden`；
   全部行为写入事件日志，只辅助记录和检查。
